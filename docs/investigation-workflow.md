# 代码调查与 VS Code

在聊天任务菜单选择“定位改动位置”，输入需求。发送前可查看文件、行范围和检索原因；范围变化后需要重新准备。每次最多发送 12 个文件，问题、历史与源码合计最多 60,000 字符。

检索使用标识符拆词、中文关键词、低权重相关术语和有界的一跳静态依赖。相关术语匹配不代表语义确认；文件依赖不代表函数调用。存在歧义时保留文件范围，并提供其他命中定义供选择。依据不足时可在范围面板执行本地补充搜索，不会因此调用模型。

桌面版打开本地仓库后，可以从源码标题或调查候选选择“在 VS Code 中打开”。首次会查找常见安装位置；未找到时选择 `Code.exe`，之后记住程序位置。跳转前会检查会话、源码哈希及行号。源码变化后先重新定位。此功能只打开文件，不运行任务或修改源码。

GitHub 快照和浏览器版通过“复制调查摘要”衔接编辑器。摘要包含问题、核对状态、依据位置、版本与待确认事项，不附独立源码副本。调查仍有内存修改时会标注尚未保存。

回到 RepoLens 后，现有监听会更新快照。变化的调查依据继续标记需要复核；重新找到位置并不代表旧结论仍然正确。

## 离线检索评测

`node scripts/evaluate-investigation-retrieval.mjs` 运行 24 个固定任务，输出逐题结果与分语言指标。素材来自六个公开仓库的固定提交，原始源码及许可证保存在 `fixtures/investigation-retrieval.json`。这是精选源码子集，不能替代完整大型仓库评测。脚本不会执行样例代码，也不调用模型。

“依据不足”时不会把兜底文件列表计为命中。范围覆盖按人工标注区间计算；无关字符比例实际指“标注关键区间之外的字符比例”，其中可能仍有有用上下文。真实用户补充搜索次数和模型结论质量需要另行人工评估。
## 2026-10-29 调查准确性复验

路线冲突副本保留步骤、引用及上下文的合法扩展字段；路线签名仍只计算既有规范字段。精确标识符保留大小写；无法区分的定义要求调整范围。

生产和离线评测共用 `prepareAiContext` 检查范围、历史字符和发送预算。`scopeRequired` 不再计为自动发送成功。以下命令不调用模型，也不执行样例程序：
