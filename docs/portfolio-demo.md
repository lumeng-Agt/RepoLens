# RepoLens 五分钟演示脚本

## 演示准备

1. 使用仓库内的独立演示项目 `fixtures/ai-integration-sample`。若要避免触碰原目录，可在临时目录复制整个文件夹后打开副本。
2. 确认 Windows 桌面包已启动，或在终端运行 `npm run dev`，使用浏览器开发版。模型设置页填写可用的 Chat Completions 兼容服务、模型与密钥；密钥只保留在本地服务内存中。
3. 在 RepoLens 中打开上述本地仓库，确认文件树含 `src/index.ts`、`src/summary.ts`、`src/status.ts` 和 `src/task.ts`。
4. 提前准备一次已核验的历史回答截图，标明“历史记录/离线备用”。只有实际连接模型并确认结果后，才可称为真实模型回答；模拟模型回归结果不能冒充真实回答。
5. 若没有可用模型服务，跳过在线生成，用历史截图讲解预览、引用和过期保护流程，并明确说明现场未调用模型。

## 演示顺序

| 时间 | 操作与讲解 |
|---|---|
| 0:00–0:30 | “读陌生代码时，入口、数据结构和处理流程往往分散在多个文件。RepoLens 把目录、静态依赖、源码和带引用的 AI 问答放到同一个本地工作区。” |
| 0:30–1:20 | 打开独立演示副本。先看文件树，再看 `index.ts` 到 `summary.ts` 的依赖关系，打开源码。“这里展示静态源码引用，不代表程序的运行时调用轨迹。” |
| 1:20–2:40 | 以 `src/index.ts` 为当前文件，询问：“当前示例最终会输出什么摘要？计数经过了哪些函数？”查看服务、模型、历史和源码行范围预览；指出尚未确认时不会发送。确认后检查回答和引用，点击引用跳回对应文件与行号。“引用位置可以核对，但仍需判断它是否支持回答。” |
| 2:40–3:40 | 生成阅读路线，依次打开入口、摘要函数、状态计数和类型定义；点击步骤完成并展示进度。“路线按当前源码给出阅读顺序，用户仍能回到引用自行检查。” |
| 3:40–4:30 | 在临时演示副本中给 `src/status.ts` 增加一条注释并保存。等待本地变更更新后，回看刚才的回答或路线，展示旧引用已失效，不能跳转到过期源码。 |
| 4:30–5:00 | “RepoLens 用本地静态分析和检索组织上下文，每次发送前让用户检查并确认。当前边界是静态依赖不等于运行时调用，引用可定位不等于回答已被证明；模型效果需要按真实模型和任务评估。” |

## 离线与故障处理

- 模型服务不可用时，使用注明日期和模型的已核验历史回答截图，继续讲解预览界面和引用跳转；不要把截图说成现场生成。
- 如果模型返回缺少引用的回答，展示产品的引用校验或说明证据不足的行为，不临时编造回答。
- 如果文件变更未及时显示，手动触发重新扫描；如仍未更新，停止修改演示副本，改用事先核验的过期状态截图并注明离线备用。
- 如果 GitHub 或网络不可用，继续使用本地演示副本。这个演示流程不依赖 GitHub。

## 结束后恢复

临时演示副本可以直接删除；不要对用户真实仓库做演示修改。清除本次 RepoLens 演示产生的本地历史记录或模型设置时，使用应用提供的清理入口。
